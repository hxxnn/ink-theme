# Ink Bleed Palette: 설계

작성일 2026-11-13 · 상태: 승인 대기

## 목적과 이유
사이트의 색(테마)을 팔레트에서 골랐을 때, 화면이 **클릭한 지점에서 잉크가 번지듯** 새 색으로 바뀌게 하는 작은 라이브러리.
- 영감: codemure-official/ink-bleed-theme-changer (라이트/다크 2색 전용 데모). **코드는 복사하지 않고 처음부터 새로 쓴다.**
- 여러 사람이 각자의 사이트에 붙여 쓴다. 사이트마다 색 적용 방식이 다르고, 유리 효과(backdrop-filter)가 있을 수도 없을 수도 있다.
- 참고한 사용 사례: 사이트의 `theme.js`는 `apply(색)` 한 번으로 `<html>`의 CSS 변수를 동기 적용한다. 이런 구조에 그대로 끼울 수 있어야 한다.

## 목표
- 어떤 색 조합이든 쓸 수 있다 (라이트/다크 고정 아님). 미리 찍어 둔 이미지에 의존하지 않는다.
- 사이트의 기존 색 적용 코드를 거의 바꾸지 않고 감싸서 쓴다: `InkBleed.run(() => apply(색), 옵션)`.
- 유리 효과, 그라데이션, 이미지 배경이 있어도 화면이 정확하다.
- 의존성 없음, 빌드 불필요 (순수 JS 파일 하나). CSP(`img-src 'self' data:`)에 걸리지 않는다 (blob:, 외부 이미지, 인라인 이벤트 없음. 스타일은 CSSOM으로 적용).
- 번지는 모양은 불규칙하다: 덩어리, 가장자리 요철, 갈라지는 촉수, 앞쪽의 작은 방울, 고른 색의 테두리.

## 비목표
- 원본 같은 부드러운 안개와 가장자리 번짐 (WebGL). 1차에는 하지 않는다. 나중에 위에 덧입히는 확장 가능.
- 색 선택 UI, 색 계산(대비 보정 등)은 만들지 않는다. 사이트가 하는 일이다.
- View Transitions를 지원하지 않는 브라우저에서 번짐을 흉내 내지 않는다.

## 안티 목표 (이러면 실패)
- 번짐 중에 글자나 레이아웃이 깜빡이거나 튀는 것.
- 색 선택기 드래그처럼 연속 입력을 매번 애니메이션해서 화면이 느려지는 것.
- 사용자가 모션을 줄였는데 애니메이션하는 것.

## 접근 방법 (선택: 1번)
1. **View Transitions + JS가 계산한 `clip-path: path()`** ← 선택. 브라우저가 이전/새 화면을 직접 찍어 정확하고 가볍다. 단점: 가장자리가 뚜렷하다(안개 없음), 미지원 브라우저는 번짐 없음.
2. WebGL 셰이더 + html2canvas 캡처: 색을 고를 때마다 캡처 지연, 유리/그라데이션/이미지에서 화면 어긋남. 제외.
3. 1번 + WebGL 안개 레이어: 품질은 좋지만 두 레이어 정렬이 어렵다. 1번 완성 후 확장 후보.

## 동작 설계
**API**
```js
InkBleed.run(applyFn, { x, y, color, duration, seed, reducedMotion }) // → Promise (끝나면 resolve)
InkBleed.supported // boolean
```
- `applyFn`: 색을 적용하는 함수. View Transition의 업데이트 콜백으로 실행된다 (동기/비동기 모두 가능).
- `x, y`: 번짐 시작점(뷰포트 CSS px). 생략하면 화면 중앙. 이벤트나 요소를 받는 편의 헬퍼를 둔다.
- `color`: 번짐 가장자리에 모이는 색(#rrggbb). 생략하면 적용 후 `<html>`의 `--ink-bleed-color`, 없으면 새 화면 배경에서 뽑는다.
- `duration`: 기본 약 1.2초. `seed`: 같은 모양 재현용.

**실행 흐름**
1. 모션 줄이기 설정이거나 미지원이면 → `applyFn`만 즉시 실행하고 resolve.
2. `document.startViewTransition(applyFn)`으로 이전/새 화면을 브라우저가 캡처하게 한다.
3. 새 화면(`::view-transition-new(root)`)에 `clip-path: path(...)`를 매 프레임 갱신해 잉크 모양으로 드러낸다. 이전 화면은 그대로 둔다.
4. 같은 시계(rAF)로 가장자리 테두리를 그린다 (고정 위치 SVG 오버레이, 포인터 이벤트 없음, 끝나면 제거).
5. 마지막에는 화면 전체를 덮는 영역으로 끝나고, transition을 정리한다.
- 번짐 중에 `run`이 또 불리면 이전 transition을 건너뛰고(skip) 새로 시작한다.
- `applyFn`이 예외를 던지면 transition을 정리하고 오류를 그대로 다시 던진다.

**모양(`shape.js`, 순수 함수)**
- 각도별 반지름 `r(θ, t)`: 기본 원 + 큰 덩어리 노이즈 + 방향 로브(찌그러짐) + 촉수(가는 가시, 길이는 방향마다 다르고 끝으로 갈수록 좁아짐) + 시간에 따른 느린 변화.
- 마지막 구간에서 화면 전체를 덮도록 균일하게 키우는 보정 (가장 먼 모서리까지 반드시 덮는다).
- 앞쪽의 작은 방울은 `path()`의 별도 서브패스(작은 원)로 만든다.
- 노이즈는 시드 기반의 자체 구현. 같은 시드면 같은 모양.

## 제약
- 대상: View Transitions를 지원하는 브라우저 (Chrome/Edge, Safari 18+, Firefox 최신). 미지원은 즉시 적용.
- 한 번에 하나의 번짐만 돈다.
- 연속 입력(색 선택기 드래그, 슬라이더)에는 쓰지 않는 것이 권장 사용법. 문서에 적는다.

## 구현자에게 맡기는 것
- 프레임 수/path 점 개수 등 성능 튜닝 (모바일에서 부드러움 기준).
- `::view-transition`에 CSS 변수와 clip-path를 적용하는 구체적 방법. 브라우저별 차이는 직접 확인한다.
- 노이즈 알고리즘의 세부와 촉수 수치.

## 산출물과 검증
- `src/ink-bleed.js` (브라우저용 단일 파일, `window.InkBleed`로 노출), `src/shape.js` (순수 모양 계산).
- `demo/index.html`: 팔레트 몇 개와 유리/그라데이션/이미지 배경 토글로 확인하는 데모. 사이트의 `theme.js`처럼 `apply`를 감싸는 예제 포함.
- `README.md`(사용법, 지원 브라우저, 권장/비권장), `LICENSE`(MIT, 본인 이름만).
- 검증: 모양 함수의 단위 테스트(같은 시드 → 같은 결과, 마지막에 화면 전체 덮음), Playwright(Chromium)로 데모 실행 후 transition이 끝나고 최종 화면이 새 색인지 확인.
